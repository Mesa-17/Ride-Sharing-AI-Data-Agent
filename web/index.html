Ride-sharing data agent

Ask a question about a ride-sharing database (5 tables, about 61,000 rows). The agent writes the SQL, checks it, and runs it as a read-only user.

The data

PostgreSQL · 8 Canadian cities · January 2025 to July 2026

TableRowsWhat's in it
users10,000riders and drivers, city, province, signup date
vehicles3,000each driver's car: make, model, year
rides20,000request, pickup and dropoff times, distance, fare, surge, status, cancellation reason
payments16,073one per completed ride: amount, method, status (completed, failed, refunded)
ratings12,0001 to 5 stars and an optional comment
+ read-only

    How it stays safe. Every query is parsed first: writes, multiple statements and functions like pg_sleep are refused, and unknown tables go back to the model to fix. Then a second model checks the query answers the question. Then it runs as a database user that can only read, with a 5 second timeout.

    If a check fails for a fixable reason, the agent tries again with the reason, up to 3 times.
